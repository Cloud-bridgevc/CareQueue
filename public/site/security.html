Security and privacy

Minimum necessary, by default

CareQueue is built to hold as little sensitive information as coordination requires, to show it only to the people who need it, and to record who saw what.

Access control

Five roles — admin, scheduler, supervisor, auditor and caregiver — with server-side permission checks on every request. Caregivers see only their own visits. Care-observation notes need a separate grant and are never summarized.

Data minimization

Clients appear by ID and initials. Addresses and access codes stay in a separate secure record. Notifications say "2 items need review", never the details.

Audit logging

Every change, sign-in, denied request and sensitive view is written to an append-only, hash-chained log. Auditors can verify the chain from the dashboard.

Configurable retention

Set retention per record type — handover notes, AI drafts, resolved issues, visit records, leads. Run a dry run first; every purge is logged.

Encryption

TLS 1.2+ in transit. PostgreSQL (Amazon RDS) and Amazon S3 encrypted at rest with AWS KMS; Enterprise customers can use their own keys.

Separation from sales tools

Our CRM receives business contact and deal information only. Payloads are built from an allowlist; client, caregiver, visit and incident data are blocked.

Responsible use of AI

  • AI is used to draft administrative summaries and report wording. Scheduling and confirmation checks are deterministic rules.
  • Only notes in administrative categories that the requester is authorized to read are sent. Phone numbers, emails and codes are redacted first.
  • The model is instructed not to diagnose, recommend treatment or assess safety. Drafts are scanned for clinical language and blocked from approval until edited.
  • Every draft is hidden until a different authorized supervisor approves it.
  • Models run in Amazon Bedrock within your AWS region. Prompts and outputs are not used to train models.

Infrastructure

  • Hosted on AWS: PostgreSQL on Amazon RDS, documents in Amazon S3 with Block Public Access and Object Lock for audit exports, AWS Lambda for notifications and background checks.
  • Private subnets, least-privilege IAM roles per function, secrets in AWS Secrets Manager.
  • Row-level security isolates each agency's data in the database.
  • Business Associate Agreement available on Enterprise.
